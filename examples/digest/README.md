# Пример: дайджест сообщений с LLM-саммари (stateful-процессор)

Боевой сценарий angarion с **пользовательским stateful-процессором**:
сообщения из группы **A** накапливаются, и при срабатывании условия
сброса батч прогоняется через локальную модель (Ollama) и единой
**сводкой** уходит в группу **B**.

Пример показывает сразу оба «трансформирующих» кирпича M4:

- **stateful-процессор** — как написать **свой** процессор с состоянием
  в `svc.state`, накоплением и периодическим сбросом
  ([`processor.py`](processor.py));
- **LLM-вызов** — переиспользуя ту же тонкую границу, что и встроенный
  процессор `llm`.

И, главное, демонстрирует **идемпотентность под at-least-once**:
повторная доставка одного и того же события не задваивает накопитель и
не отправляет дайджест дважды.

## Что нужно

- Установленный проект с extra:
  `uv sync --extra telegram --extra sqlite --extra llm`.
- **Ollama** с подтянутой моделью (по умолчанию `qwen2.5:3b`):

  ```bash
  ollama serve        # если ещё не запущена (слушает 127.0.0.1:11434)
  ollama pull qwen2.5:3b
  ```

  Полегче — `gemma2:2b`; тогда поправь `model` в `app.toml`.
- Telegram-аккаунт, **состоящий в обеих группах** A и B.
- `api_id` / `api_hash` — с <https://my.telegram.org> → API development
  tools.
- `id` групп (вида `-100…`) — например, переслав сообщение из группы боту
  `@username_to_id_bot`.

## Настройка

1. Подставь `id` групп в [`app.toml`](app.toml) (`sources` / `targets`)
   и при желании поправь параметры сброса (`n`, `max_age_s`) и промпты.
2. Задай секреты в окружении (не в файлах — они не должны попасть в git):

   ```bash
   export ANGARION_ACCOUNTS__MAIN__API_ID=12345
   export ANGARION_ACCOUNTS__MAIN__API_HASH=0123456789abcdef0123456789abcdef
   ```

## Запуск

```bash
examples/digest/run.sh
```

Скрипт «всё в одном» (идемпотентный): генерирует ключ шифрования сессии в
`angarion-data/session.key`, применяет миграции БД (`angarion-data/app.db`),
при первом запуске проводит интерактивную авторизацию (`angarion login`),
затем запускает конвейер через [`run.py`](run.py).

Проверка: напиши в группу A несколько сообщений. Как только их наберётся
`n` (по умолчанию 5) **или** батчу исполнится `max_age_s` (5 минут) и
придёт следующее сообщение — в группу B прилетит одна сводка.
`Ctrl+C` — корректная остановка.

Весь рантайм (БД, ключ, сессия) — в `angarion-data/` рядом со скриптом;
этот каталог в `.gitignore`, секреты в репозиторий не попадают.

## Как это устроено

Процессор `digest` ([`processor.py`](processor.py)) реализует контракт
`(event, ctx, svc) -> ProcessingResult`:

- **состояние** — одна Pydantic-модель `DigestState` в `svc.state` под
  ключом `state` (KV с JSON-значениями, namespace = имя пайплайна, §10.3);
- на каждом событии текст добавляется в накопитель `items`, его
  `dedup_key` — в `seen`; ничего не отправляется, вердикт `DROP`;
- при сбросе (`len(items) >= n` или возраст накопления `>= max_age_s`)
  батч склеивается и уходит в модель; ответ единым `OutboundRecord`
  доставляется на **каждую** `ctx.targets`, накопитель очищается;
- **идемпотентность под at-least-once:** учтённые `dedup_key` лежат в
  `seen` (текущий батч) и в ограниченном хвосте `recent` (последние
  `recent_cap` сброшенных). Повтор события до сброса не задваивает
  `items`, повтор триггера после сброса не запускает второй сброс.
  Накопление **персистится до** вызова LLM — если вызов упадёт и worker
  переотправит событие, `dedup_key` уже учтён и повтор не задвоит запись.

### Регистрация кастомного процессора

`angarion run` находит процессоры через entry points `angarion.processors`
— так подключаются встроенные и пакеты сторонних разработчиков. Здесь
процессор живёт одним файлом без упаковки, поэтому
[`run.py`](run.py) регистрирует его в процессе (`register(DIGEST)`) и
запускает штатный run-loop библиотеки. Если оформляешь процессор как
устанавливаемый пакет — объяви его в своём `pyproject.toml`:

```toml
[project.entry-points."angarion.processors"]
digest = "my_pkg.digest:DIGEST"
```

тогда обычного `angarion run --config app.toml` достаточно, `run.py` не нужен.

## Минимальный встроенный `llm` (без своего кода)

Если нужна не сводка-накопление, а суммаризация/перевод **каждого**
сообщения по отдельности — это умеет встроенный процессор `llm`, без
кастомного кода. Замени секцию пайплайна на:

```toml
[pipelines.summarize]
processor = "llm"
events = ["new"]
sources = [{ account = "main", address = "-100AAAAAAAAAA" }]
targets = [{ account = "main", address = "-100BBBBBBBBBB" }]

[pipelines.summarize.processor_config]
base_url = "http://localhost:11434/v1"
model = "qwen2.5:3b"
system_prompt = "Ты — суммаризатор. Сократи сообщение до сути на русском."
user_prompt = "Сократи: {{ text }}"
```

и запускай штатным `uv run angarion run --config app.toml` (без `run.py` —
`llm` уже зарегистрирован под extra `angarion[llm]`).

## Заметки

- **Сброс по `max_age_s` событийный.** Worker конкурентен = 1 и
  событийно-управляем (§6.3): возраст батча проверяется только при
  приходе сообщения. При полном затишье в группе A дайджест ждёт
  следующего сообщения — фонового шедулера по «настенному» времени нет
  (осознанно, как honored FloodWait в M3).
- **Окно at-least-once конечно.** Хвост `recent` ограничен `recent_cap`:
  повтор очень старого события (выпавшего из хвоста) теоретически может
  попасть в новый батч. Для демо `100` с запасом.
- **Грань потери при сбое.** Накопитель очищается внутри `process`, до
  того как worker durably зафиксирует исходящее. Если процесс упадёт
  ровно между возвратом `DELIVER` и записью в outbox — конкретная сводка
  может потеряться (а не задвоиться). Транзакционный outbox, закрывающий
  и эту грань, — за рамками примера.
- `queue = "memory"`: при `Ctrl+C` необработанное в очереди теряется, но
  catch-up доберёт на следующем `run`. Для боевого режима —
  `backend = "persistqueue"` (extra `persistqueue`).

## Если код авторизации не приходит

`angarion login` запрашивает код у Telegram; **канал доставки выбирает
Telegram**. Из-под VPN код может уйти не в приложение, а по SMS/звонку.
Если кода нет — проверь служебный чат **Telegram** (`777000`), SMS и
входящие звонки; попробуй без VPN.

## Если сводка не приходит

- Проверь, что Ollama запущена и модель скачана:
  `curl http://localhost:11434/v1/models` должен вернуть список с `model`
  из `app.toml`.
- Дайджест ждёт `n` сообщений или истечения `max_age_s` **и** следующего
  события — пришли ещё одно сообщение, чтобы инициировать проверку сброса.
